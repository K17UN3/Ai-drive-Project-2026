# AI質問機能 タスク計画書 (`docs/ai/tasks.md`)

## 1. 概要

本ドキュメントは、既存の Express / TypeScript プロジェクトに対して AI 質問機能を段階的に安全に実装・検証するための詳細なタスク手順を定義する。
各作業は「要件・設計への準拠」「既存機能（TOP/TODO）の非破壊」「段階的な動作確認」を担保するように設計されている。

---

## 2. タスク一覧とフェーズ区分（標準課題／発展課題）

本計画は授業時間内に完了すべき**標準課題**と、品質向上や監視強化のための**発展課題**を明確に区別する。

### 【標準課題】
* **TASK-01**: 共通ひな型とデモ停止（ルーティング・デモガード）
* **TASK-02**: SQLとDBログ基盤（`ai_qa_logs` テーブルおよびモデル作成）
* **TASK-03**: 模擬回答（モック）の保存・API疎通
* **TASK-04**: Gemini API (実AI) 接続とタイムアウト処理
* **TASK-05**: 初期表示 UI と 0 件・エラー状態管理
* **TASK-06**: 送信・待機・安全なテキスト描画 (XSS対策)
* **TASK-07**: 異常系テストと既存機能回帰テスト
* **TASK-08**: Preview環境確認・本番運用デモ準備・提出確認

### 【発展課題】
* **TASK-09**: 過去質問ログ取得 API と一覧表示 UI の実装
* **TASK-10**: 詳細エラーログ出力およびパフォーマンス監視ログの強化

### TASK-01: 共通ひな型とデモ停止
* **作業ID**: `TASK-01`
* **区分**: 標準課題
* **対応REQ・DES**: `REQ-AI-F001`, `REQ-AI-N001`, `REQ-AI-N003`, `DES-AI-01`, `DES-AI-06`, `DES-AI-08`
* **変更対象ファイル**:
  * `tsconfig.json`
  * `index.ts`
  * `src/apps/ai/aiRouter.ts` (新規)
  * `src/apps/ai/aiController.ts` (新規)
  * `views/ai/index.ejs` (新規)
* **作業内容**:
  1. `tsconfig.json` の `"include"` に `"src/**/*"` を追加し、ビルド対象を広げる。
  2. `src/apps/ai/` 配下に `aiRouter.ts` および `aiController.ts` の最小限の骨組みを作成する。
  3. `GET /ai` (画面表示) と `POST /api/ai/ask` (API) のエンドポイントを仮定義する。
  4. `aiController` の先頭に環境変数 `GEMINI_API_KEY` の存在チェックを追加する（未設定時は即座に HTTP 503 を返却）。
  5. `index.ts` に `express.json({ limit: '10kb' })` を設定し、`aiRouter` をマウントする。
* **確認方法**:
  * `.env` の `GEMINI_API_KEY` を未設定の状態で `npm run dev` を実行し、`curl` またはブラウザで `GET /ai` および `POST /api/ai/ask` にリクエストを送信する。
  * 既存の `/` (TOP) および `/todo` へアクセスする。
* **期待結果**:
  * `GEMINI_API_KEY` 未設定時、AI API が 503 Service Unavailable レスポンスを返却すること。
  * 既存の TOP ページ (`/`) および TODO ページ (`/todo`) が一切の影響を受けず従来通り正常動作すること。
* **次へ進む条件**: `GEMINI_API_KEY` 未設定で両APIが 503 を返し、既存の TOP・TODO が正常動作すること。

### TASK-03: 模擬回答（モック）の保存・API疎通
* **作業ID**: `TASK-03`
* **区分**: 標準課題
* **対応REQ・DES**: `REQ-AI-F002`, `REQ-AI-F003`, `REQ-AI-D001`, `REQ-AI-D002`, `DES-AI-02`, `DES-AI-03`, `DES-AI-10`
* **変更対象ファイル**:
  * `src/apps/ai/aiController.ts`
  * `src/apps/ai/aiService.ts` (新規)
* **作業内容**:
  1. `src/apps/ai/aiService.ts` を新規作成し、外部 API を呼ばずに模擬回答テキスト（「これはモック回答です」）を返す関数を定義する。
  2. `aiController.ts` で `req.body.question` の入力型および文字数（トリム後1〜1,000文字）バリデーションを実装する（不正時は 400/422 返却）。
  3. Valid なリクエストに対し、モックの `aiService` を呼び出し、結果受領後にバックグラウンド（非同期 `catch` 付）で `aiModel.saveLog()` を実行して 200 OK を返却する。
* **確認方法**:
  * `GEMINI_API_KEY` を有効化し、`POST /api/ai/ask` へ Valid な JSON (`{"question": "テスト"}`) を送信する。
  * 空文字や1,001文字以上の不正 JSON を送信する。
  * DB の `ai_qa_logs` を `SELECT * FROM ai_qa_logs;` で確認する。
* **期待結果**:
  * Valid なリクエストに対して 200 OK とモックの回答 JSON (`{ status: 'success', data: { answer: ... } }`) が返ること。
  * 不正なリクエストに対して外部 API や DB を呼ばずに 400/422 エラーが返ること。
  * `ai_qa_logs` テーブルに質問とモック回答、実行時間が記録されること。
* **次へ進む条件**: 実APIなしの状態でバリデーション・モック応答・DB保存が正常に行えること。

* **期待結果**:
  * 正常送信時、Gemini API から生成されたリアルな日本語回答が 200 OK で返り、`ai_qa_logs` に記録されること。
  * キー無効時、サーバーがクラッシュせず 500 エラーレスポンスが正しく返却されること。
* **次へ進む条件**: 実 Gemini API と接続でき、正常応答の受領・エラー制御・ログ保存が動作すること。

### TASK-06: 送信・待機・安全なテキスト描画 (XSS対策)
* **作業ID**: `TASK-06`
* **区分**: 標準課題
* **対応REQ・DES**: `REQ-AI-F001`, `REQ-AI-F002`, `REQ-AI-F003`, `REQ-AI-F004`, `DES-AI-01`, `DES-AI-03`, `DES-AI-04`
* **変更対象ファイル**:
  * `public/ai/ai.js` (新規)
  * `views/ai/index.ejs`
* **作業内容**:
  1. `public/ai/ai.js` を作成し、フロントエンドの Fetch API 通信処理を実装する。
  2. 送信ボタン押下時、フロント側の文字数チェック（空文字・1,000文字超）を行い、不正時は通信せずに警告を表示する。
  3. 通信開始時に送信ボタンを非活性化 (`disabled = true`) し、ボタンテキストを「回答生成中...」に変更する。
  4. レスポンス受領後、`element.textContent` を使用して回答テキストを描画する（`innerHTML` 禁止による XSS 対策）。
  5. 通信終了後（成功・失敗問わず）、ボタンの非活性状態を解除して復帰させる。
* **確認方法**:
  * 画面上から質問を入力して送信し、ローディング表示とボタンの二重押し防止を確認する。
  * `script` タグを含む質問（例: `<script>alert('XSS')</script>`）を送信し、回答描画時にスクリプトが実行されないことを確認する。
* **期待結果**:
  * 画面遷移なし（非同期）でスムーズに回答が表示されること。
  * 通信中にボタンが連打できず、ローディング状態が可視化されること。
  * HTML タグが無害な文字列として安全に表示（XSS対策完了）されること。
* **次へ進む条件**: フロント通信、連投防止、ローディング制御、安全なテキスト描画がブラウザ上で正常動作すること。
