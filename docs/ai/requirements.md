# AI質問機能 要件定義書 (`docs/ai/requirements.md`)

## 1. 概要

### 1.1 背景・目的
本アプリケーションは Express / TypeScript で構築された既存の Web アプリケーションである。ユーザーの利便性向上を目的として、疑問点や質問を入力した際に AI（LLM）が迅速に適切な回答を返却する「AI質問機能」を追加する。既存の TODO 機能で採用されているアーキテクチャパターンを踏襲し、保守性・拡張性の高い構成で実装を行う。

### 1.2 対象ユーザー
* 本Webアプリを利用する一般ユーザーおよび管理者。

### 1.3 対象範囲（スコープ）
* **対象内**: 
  * AI質問画面（UI）の提供（`views/ai/index.ejs`, `public/ai/ai.js`）および TOP/TODO 画面へのコンポーネント組込
  * AI質問APIエンドポイント（`POST /api/v1/ai/ask`）およびサーバー側AI連動処理
  * 入力バリデーションおよびエラーハンドリング（画面へのエラー表示を含む）
  * 対話品質分析用ログ（`ai_qa_logs`）の非同期DB保存
  * 既存アーキテクチャに沿ったモジュール追加（`src/apps/ai/` 配下）およびルーティング追加（`index.ts`）
* **対象外**: 
  * ログイン・ユーザー認証機能
  * 会話履歴の複数ターン記憶・継続コンテキスト機能
  * Markdown描画・リッチテキスト表示等の特殊表現

## 3. 業務条件・挙動定義

### 3.1 入力条件
* **質問テキスト仕様**:
  * 必須入力。前後の空欄をトリム後、1文字以上 1,000文字以内とする。
  * 空文字、または空白のみの入力はフロントエンドおよびバックエンドの双方でバリデーション弾きを行う（外部AIは呼び出さない）。

### 3.2 履歴条件（0件含む）
* **会話履歴の扱い**:
  * 会話履歴の複数ターン保持・継続会話（過去コンテキストの送信）は行わない（1回ごとの単発問答）。
  * 画面初回表示時（履歴0件時）は回答表示エリアおよびエラー表示エリアを**非表示（hidden）**とし、正常な初期状態として扱う。

### 3.3 保存条件
* **保存動作**:
  * AIの応答完了後、バックグラウンド（非同期）で `ai_qa_logs` テーブルにパラメータ化クエリを用いて対話ログを記録する。
  * **AI成功・DB失敗の切り分け**: DB障害等でログ保存が失敗した場合でも、システムログへエラー出力を行うのみとし、ユーザーには HTTP 200 OK で AI 回答を正常返却する。

### 3.4 0件条件（空回答・回答不能時）
* **0件（空回答）時の動作**:
  * AIからの応答テキストが空（0文字）と判定された場合、システムエラーとはせず「回答を取得できませんでした。質問内容を少し変えて再度お試しください。」というメッセージをテキスト表示する。

### 3.5 失敗・再送条件
* **通信・処理失敗時の動作**:
  * 外部APIのレスポンスコード異常（4xx/5xx）、ネットワーク不通、タイムアウト発生時は、画面上にエラー表示を行う。
* **再送処理**:
  * 自動再試行（リトライ）は行わない。
  * ユーザーが画面上のエラーメッセージを確認し、手動で再送信ボタンを押下可能とする。

### 3.6 公開停止・非活性化条件
* **サービス非活性条件（デモ停止ガード）**:
  * サーバー起動時またはリクエスト受信時、必要な環境変数（`GEMINI_API_KEY` 等）が設定されていない場合、APIエンドポイントの処理先頭で即座に HTTP 503 (Service Unavailable) を返し、AI呼び出しやDBアクセスを行わずに安全に拒否する。
