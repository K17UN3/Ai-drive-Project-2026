# リアルタイムチャット機能 追加要望書 (`01_request.md`)

## 1\. 概要

本プロジェクト（Express / TypeScript 製の既存Webアプリケーション：TOP / TODO / AI質問アプリ）に、**ユーザー間リアルタイムチャット機能（`/chat`）** を新規実装する。 本機能はユーザー同士のコミュニケーション専用とし、AIによる自動応答は含まない。

---

## 2\. 背景・目的

- **目的**: 本アプリを利用するユーザー同士が、リアルタイムで円滑にメッセージのやり取りを行えるようにする。  
- **対象ユーザー**: 本アプリを利用する一般ユーザーおよび管理者。  
- **利用技術**: Express / TypeScript / EJS / Neon（PostgreSQL）/ Socket.IO

---

## 3\. 要件定義（要望レベル）

### 3.1. 機能要件

1. **チャット画面の提供（EJS）（`WISH-CHAT-001`）**

   - EJS テンプレート（`views/chat/index.ejs`）を用いて、`/chat` でアクセスできるチャット画面を提供する。  
   - ユーザーが「ユーザー名」と「コメント」を入力し、送信できること。  
2. **リアルタイム送受信と履歴保存（`WISH-CHAT-002`）**

   - `Socket.IO` を用いて、投稿されたメッセージを同一ルームの接続クライアントへリアルタイム配信する。  
   - 送信された会話データ（ユーザー名・コメント・作成日時）を Neon DB（PostgreSQL）に保存し、画面の初期表示や再接続時に最新履歴（最新20件）を取得・表示できるようにする。  
3. **複数インスタンス間のブロードキャスト対応（`WISH-CHAT-003`）**

   - 複数インスタンス環境（Vercel等のサーバーレス・マルチインスタンス環境）での稼働を考慮し、Redis Adapter または DB 同期（定期ポーリング／再取得）により、異なるインスタンスに接続しているユーザー間でもメッセージの整合性を保てる構成とする。  
4. **ルーム定員制限（1部屋5人まで）（`WISH-CHAT-004`）**

   - チャットルームの同時アクセス・参加人数は **1部屋あたり最大5名** までとする。  
   - すでに5名が参加している場合、**6人目以降のユーザーはチャットルームへアクセス・参加できない** よう制限し、満席である旨の案内を画面に表示する。  
5. **入力検証・エラーハンドリング（`WISH-CHAT-005`）**

   - WebSocket通信エラー、API通信エラー、DB障害、入力値不正（空文字・空白のみ・文字数超過など）が発生した場合に、ユーザーフレンドリーなエラーメッセージを画面に表示する。  
   - サーバーがクラッシュしないよう、適切な例外処理とグローバルエラーハンドラーへの連携を行う。

### 3.2. 非機能要件

- **アーキテクチャの踏襲**:  
  - 既存の TODO アプリ（`src/apps/todo/`）の設計パターン（Router / Controller / Service / Model の分離）に倣い、チャット機能専用のディレクトリ（`src/apps/chat/`）を新設する。  
- **セキュリティ・機密情報管理**:  
  - DB 接続文字列（`DATABASE_URL`）や Redis 接続情報等の機密情報はソースコードに直書きせず、`dotenv` を利用して環境変数からサーバー側のみで安全に読み込むこと。ブラウザへ機密情報を露出させないこと。  
  - ユーザー名やコメントの画面描画時は XSS 対策（EJS の `<%= ... %>` エスケープ、JS での `textContent` 利用）を徹底すること。  
- **既存機能への影響ゼロ**:  
  - 既存の TOP 画面、TODO 機能、AI質問機能、ルーティング、DB接続、404ハンドリング、エラーハンドリングを一切破壊しないこと。

## 4\. 実装・配置スコープ案

### 4.1. 追加・修正予定のファイル

| 区分 | ファイルパス | 役割 |
| :---- | :---- | :---- |
| **ルーティング** | `src/apps/chat/chatRouter.ts` | `/chat` 画面および `/api/chat/*` のエンドポイント定義 |
| **コントローラー** | `src/apps/chat/chatController.ts` | 満席判定・履歴取得・リクエスト検証・エラー連携 |
| **サービス** | `src/apps/chat/chatService.ts` | `Socket.IO` 制御・定員管理（最大5名）・ブロードキャスト制御 |
| **モデル** | `src/apps/chat/chatModel.ts` | Neon DB（`chat_messages`）への保存・取得・アクティブ人数管理 |
| **ビュー** | `views/chat/index.ejs` | リアルタイムチャット画面の EJS テンプレート・満席時アクセス制限表示 |
| **静的ファイル** | `public/chat/chat.js` | `Socket.IO` クライアント制御・画面描画・再接続および同期処理 |
| **DB定義SQL** | `sql/chat/040_create_chat_messages.sql` | チャットメッセージ保存用テーブル作成SQL |
| **サーバー統合** | `index.ts` / `local.ts` | ルーターのマウント（`app.use('/chat', ...)` 等）と `Socket.IO` サーバーの初期化 |

### 4.2. 必要な外部パッケージ・環境変数

- **パッケージ追加**:  
  - `socket.io`（サーバー側 WebSocket 通信）  
  - `@socket.io/redis-adapter` / `redis`（複数インスタンス間ブロードキャストを行う場合）  
- **環境変数（追加・確認）**:  
  - `DATABASE_URL` / `DATABASE_URL_POOLED`（Neon DB 接続用・既存共有）  
  - `REDIS_URL`（マルチインスタンスで Redis Adapter を使用する場合）
